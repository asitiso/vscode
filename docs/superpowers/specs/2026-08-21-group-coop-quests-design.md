# 그룹 공동 퀘스트 + MVP 설계

## 목적

그룹 멤버들이 서로 다른 운동을 하더라도 각자의 운동이 하나의 공동 목표에 기여하도록 만든다. 기존의 오늘/이번 주 순위는 유지하되, 경쟁만 있는 화면이 아니라 "같이 채우는 재미"를 추가한다.

핵심 원칙은 다음과 같다.

- 운동 종목은 비교하지 않는다.
- 현재 그룹 데이터에서 주간 진행도를 계산한다.
- 운동시간이 긴 종목이 MVP를 독점하지 않도록 시간 기여에 상한을 둔다.
- 1차 버전은 별도 아이템/XP 보상을 추가하지 않는다.
- 새 영구 저장 테이블이나 게임 세이브 스키마를 만들지 않는다.

## 사용자 경험

그룹 상세 화면에서 기존 `LIVE WORKOUT`/랭킹 영역 위에 `이번 주 공동 퀘스트` 패널을 노출한다.

패널에는 세 개의 미션과 진행 바가 있다.

1. `👟 모두의 출석`
   - 이번 주 한 번 이상 운동한 멤버 수를 센다.
   - 목표 인원 = `ceil(현재 그룹 인원 × 0.7)`.
   - 최소 목표는 1명이다.
   - 예: 4명 그룹이면 3명, 10명 그룹이면 7명.

2. `⏱️ 함께 채운 시간`
   - 현재 멤버들의 이번 주 인정 운동시간을 합산한다.
   - 목표 = `현재 그룹 인원 × 60분`.
   - 예: 4명 그룹이면 240분.
   - 실제 합산시간은 목표를 넘어도 그대로 표시하고, 진행 바만 100%에서 고정한다.

3. `🎯 각자의 목표, 하나의 팀`
   - 개인 주간 목표 달성률이 100% 이상인 멤버 수를 센다.
   - 목표 인원 = `ceil(현재 그룹 인원 × 0.5)`.
   - 최소 목표는 1명이다.
   - 예: 4명 그룹이면 2명, 5명 그룹이면 3명.

세 미션이 모두 완료되면 패널 상단 상태를 `🏆 이번 주 우리 그룹 미션 COMPLETE!`로 바꾼다. 별도 보상 수령 버튼은 만들지 않는다.

## 이번 주 MVP

공동 퀘스트 아래에 `🔥 이번 주 MVP`를 한 명 표시한다. MVP는 단순 운동시간 1위가 아니라 다음 기여 점수의 합으로 계산한다.

- 이번 주 운동 참여: `+1`
- 운동시간 30분마다 `+1`, 최대 `+4`
- 개인 주간 목표 50% 이상: `+1`
- 개인 주간 목표 100% 이상: 추가 `+2`

최대 점수는 8점이다.

예시:

- 35분 운동, 목표 30%: 2점
- 70분 운동, 목표 65%: 4점
- 150분 운동, 목표 100%: 8점

시간 점수는 `floor(weeklySeconds / 1800)`으로 계산하고 4점에서 제한한다. 운동을 전혀 하지 않은 멤버는 0점이다.

### MVP 동률 처리

점수가 같으면 다음 순서로 결정한다.

1. 개인 주간 목표 달성률이 높은 사람
2. 이번 주 운동시간이 긴 사람
3. 닉네임 오름차순

모든 멤버의 점수가 0점이면 MVP를 표시하지 않고 `이번 주 첫 기여자를 기다리고 있어요` 상태를 표시한다.

## 주간 범위와 가입 시점

주간 기준은 기존 그룹 기능과 동일하게 월요일 시작을 사용한다.

새 멤버가 주중에 그룹에 가입했을 때 가입 이전의 운동기록이 공동 퀘스트에 소급 반영되지 않도록 한다.

- `group_members.joined_at`을 `loadGroupDetail`에서 함께 읽는다.
- 각 멤버의 인정 시작일은 `max(이번 주 월요일, 가입일)`이다.
- `group_activity_daily`는 일 단위 집계이므로 가입 당일 기록은 해당 날짜 전체를 인정한다.

이 규칙은 DB 스키마 변경 없이 기존 `joined_at` 컬럼을 사용한다.

## 데이터/아키텍처

### 데이터 소스

기존 `GroupMemberSummary`가 제공하는 다음 필드를 공동 퀘스트 계산의 기본 입력으로 사용한다.

- `weeklySeconds`
- `weeklyGoalPercent`
- `userId`
- `nickname`

`weeklySeconds` 자체는 `loadGroupDetail`에서 가입 시점을 고려해 계산하도록 보정한다.

### 순수 계산 모듈

새 파일 `src/group/groupQuestSelectors.ts`를 만든다.

이 모듈은 React나 Supabase에 의존하지 않고 멤버 배열만 받아 다음 값을 반환한다.

- 세 미션의 current/target/completed/progressPercent
- 전체 완료 여부
- MVP 멤버와 기여 점수

예상 공개 함수:

```ts
buildGroupQuestView(members: GroupMemberSummary[]): GroupQuestView
```

진행률과 MVP 규칙을 한 곳에 모아 UI와 데이터 로딩 코드를 단순하게 유지한다.

### UI 컴포넌트

새 파일 `src/screens/group/GroupCoopQuestPanel.tsx`를 만든다.

역할:

- `buildGroupQuestView` 결과 렌더링
- 세 개 미션의 진행 바/수치 표시
- 전체 완료 상태 표시
- MVP 카드 또는 첫 기여 대기 상태 표시

`GroupDetailScreen.tsx`는 기존 그룹 정보를 불러온 뒤 `GroupCoopQuestPanel`에 `detail.members`만 전달한다.

스타일은 기존 그룹 화면과 시각적으로 이어지도록 `GroupScreens.css`에 추가한다. 새로운 이미지 에셋은 필요하지 않고 이모지/텍스트/진행 바만 사용한다.

## 기존 기능과의 관계

- 기존 `GroupMotivationPanel`의 오늘/이번 주 랭킹은 그대로 유지한다.
- 기존 실시간 운동 중 표시도 유지한다.
- 공동 퀘스트는 랭킹을 대체하지 않고 랭킹 위에 추가한다.
- 기존 그룹 생성/가입/탈퇴/내보내기 동작은 변경하지 않는다.
- 기존 개인 운동 기록/개인 PR/수집/세이브 스키마에는 영향을 주지 않는다.

## 예외 처리

- 그룹 인원 1명: 출석 목표 1명, 시간 목표 60분, 개인목표 완료 목표 1명으로 동작한다.
- `weeklyGoalPercent`가 100을 초과해도 목표 완료 판정은 `>= 100`으로 한다.
- 음수/비정상 운동시간이 들어오면 계산 모듈에서 0 이상으로 정규화한다.
- 진행 바는 항상 0~100% 범위로 제한한다.
- 멤버 배열이 비어 있으면 모든 미션 target/current를 0으로 만들고 완료 상태는 false로 한다. 정상 UI에서는 발생하지 않지만 selector는 안전하게 처리한다.

## 테스트 전략

TDD로 구현한다.

### `groupQuestSelectors.test.ts`

- 4명 그룹의 출석 목표가 3명인지
- 4명 그룹의 시간 목표가 240분인지
- 5명 그룹의 개인목표 완료 목표가 3명인지
- 세 미션의 완료/미완료 판정
- 진행률 100% 상한
- MVP 시간점수 4점 상한
- MVP 최대 8점
- 목표 달성률 50%/100% 경계
- MVP 동률 처리 순서
- 모두 0점이면 MVP 없음
- 빈 멤버 배열 안전 처리

### `GroupCoopQuestPanel.test.tsx`

- 세 미션 제목/수치가 렌더링되는지
- 전체 완료 문구가 조건에 맞게 노출되는지
- MVP 닉네임/기여 점수가 노출되는지
- MVP가 없을 때 대기 문구가 노출되는지

### `groupApi` 관련 테스트

- 주중 가입 멤버의 가입 이전 날짜 운동이 주간 합계에서 제외되는지
- 기존 멤버의 월요일 이후 기록은 그대로 합산되는지

- `npx tsc -b`

## 범위 밖

이번 버전에는 다음을 넣지 않는다.

- 그룹 XP/아이템/카드 보상
- 미션 완료 보상 수령 상태 저장
- 일일 미션
- 랜덤 미션 로테이션
- 그룹별 난이도 설정
- 운동 종목별 가중치
- 응원/찌르기/채팅
- MVP 히스토리 저장
- 오늘의 스타터/목표 사냥꾼/팀 부스터 같은 추가 칭호

이 항목들은 공동 퀘스트 사용성을 확인한 뒤 별도 확장 작업으로 다룬다.
