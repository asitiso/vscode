# Supabase 수동 중간 저장 설계

## 목표

기존 앱의 로컬 저장 방식을 유지하면서, 사용자가 설정 화면의 `중간 저장` 버튼을 눌렀을 때만 현재 게임 상태를 Supabase에 단일 슬롯으로 백업한다. 로그인 화면은 제공하지 않으며, 브라우저별 익명 저장키로 같은 브라우저에서만 저장과 복구가 가능하도록 한다.

## 확정 범위

- 평소 상태 변경은 기존처럼 `localStorage`에 즉시 저장한다.
- Supabase 자동 저장은 하지 않는다.
- 설정 화면의 데이터 관리 섹션에 `중간 저장`과 `중간 저장 불러오기`를 추가한다.
- Supabase 백업은 브라우저별 단일 슬롯 하나만 사용한다.
- 중간 저장 시 이전 백업을 최신 상태로 덮어쓴다.
- 로그인, 회원가입, 이메일, 비밀번호는 사용하지 않는다.
- 다른 기기 복구와 브라우저 데이터 삭제 후 복구는 지원하지 않는다.

## 저장 식별 방식

앱 최초 실행 시 `crypto.getRandomValues()`로 충분히 긴 익명 저장키를 생성한다. 원본 저장키는 브라우저 `localStorage`에만 보관하고 Supabase에는 원본을 저장하지 않는다.

Supabase 요청 전 Web Crypto API의 SHA-256으로 저장키를 해시한다. 서버에는 해시값만 전달하며, 이 값이 해당 브라우저의 단일 저장 슬롯 식별자가 된다.

## 데이터 구조

Supabase에 다음 테이블을 만든다.

```sql
anonymous_game_saves
- device_key_hash text primary key
- state jsonb not null
- client_saved_at timestamptz not null
- updated_at timestamptz not null default now()
- schema_version integer not null default 1
```

`state`에는 현재 `AppState` 전체를 JSON으로 저장한다. `client_saved_at`은 클라이언트가 중간 저장 버튼을 누른 시각이고, `updated_at`은 서버 저장 시각이다.

## 보안 구조

테이블은 프런트엔드에서 직접 조회하거나 수정하지 않는다.

- Row Level Security를 활성화한다.
- 익명 역할의 테이블 직접 `select`, `insert`, `update`, `delete` 권한은 허용하지 않는다.
- `save_anonymous_game_state`와 `load_anonymous_game_state` RPC 함수만 공개한다.
- RPC 함수는 저장키 해시와 상태 JSON을 입력받아 단일 행을 `upsert`하거나 조회한다.
- PostgreSQL 접속 문자열, 데이터베이스 비밀번호, service role 키는 앱 코드와 GitHub에 넣지 않는다.
- 프런트엔드에는 프로젝트 URL과 publishable key만 사용한다.

이 방식은 로그인 없이 저장할 수 있지만, 저장키를 확보한 사람이 해당 슬롯을 읽거나 덮어쓸 수 있다는 한계가 있다. 원본 저장키를 브라우저 밖으로 노출하지 않고 충분히 긴 무작위 키를 사용해 현실적인 추측 공격 가능성을 낮춘다.

## 앱 구성

### `src/lib/supabaseClient.ts`

- Supabase 클라이언트를 한 번만 생성한다.
- 프로젝트 URL과 publishable key를 환경변수에서 읽는다.
- 환경변수가 없으면 클라우드 저장 기능을 비활성화하고 로컬 저장은 정상 동작시킨다.

### `src/store/anonymousDevice.ts`

- 익명 저장키 생성 및 로컬 보관
- SHA-256 해시 생성
- 저장키가 없을 때만 새로 생성

### `src/store/cloudStorage.ts`

- `saveAnonymousGameState(state)`
- `loadAnonymousGameState()`
- RPC 응답 검증
- Supabase 오류를 사용자용 결과로 변환

### `src/store/storage.ts`

기존 로컬 저장 기능을 유지한다. 로컬 저장 데이터에 `localSavedAt` 메타데이터를 추가하거나 별도 키로 마지막 로컬 저장 시각을 관리한다. 기존 저장 데이터는 마이그레이션으로 계속 읽을 수 있어야 한다.

### `src/store/GameContext.tsx`

- 평소 상태 변경 시 로컬 저장만 수행한다.
- 수동 중간 저장 및 불러오기 함수를 UI에 제공한다.
- 불러온 상태는 기존 마이그레이션 함수를 통과시킨 뒤 적용한다.

## 화면 동작

설정 화면에 `데이터 관리` 섹션을 추가하거나 기존 섹션에 다음 항목을 배치한다.

### 중간 저장

- 기본 상태: `중간 저장`
- 요청 중: `저장 중...`, 버튼 비활성화
- 성공: `중간 저장 완료`
- 성공 후 마지막 저장 시각 표시
- 실패: `저장하지 못했습니다. 인터넷 연결을 확인해 주세요.`
- 실패해도 현재 로컬 데이터는 유지

### 중간 저장 불러오기

- 저장 기록이 없으면 `저장된 중간 데이터가 없습니다.` 표시
- 저장 기록이 있으면 저장 시각을 보여준다.
- 현재 로컬 데이터를 덮어쓰므로 확인 대화상자를 거친다.
- 확인 후 클라우드 상태를 기존 상태 마이그레이션 함수로 검증한다.
- 성공하면 로컬 저장소에 즉시 저장하고 앱 상태를 교체한다.
- 잘못된 JSON 또는 지원하지 않는 데이터면 복구하지 않고 오류를 표시한다.

## 충돌 및 복구 기준

앱 시작 시 Supabase를 자동 조회하지 않는다. 항상 로컬 상태로 즉시 시작한다.

클라우드 데이터는 사용자가 `중간 저장 불러오기`를 눌렀을 때만 조회한다. 로컬과 클라우드의 저장 시각은 안내 목적으로 표시하지만, 사용자가 확인하면 클라우드 저장본이 로컬 상태를 덮어쓴다.

## 오류 처리

- Supabase 연결 실패: 로컬 기능 정상 유지
- 환경변수 누락: 버튼을 비활성화하고 `중간 저장 설정이 필요합니다.` 표시
- 저장 실패: 재시도 가능, 로컬 데이터 유지
- 불러오기 실패: 현재 상태 유지
- 유효하지 않은 상태: 현재 상태 유지하고 오류 안내
- 중복 클릭: 진행 중 버튼 비활성화

## 테스트 기준

- 기존 `localStorage` 저장과 마이그레이션 테스트가 계속 통과한다.
- 익명 저장키가 최초 한 번만 생성된다.
- 같은 저장키는 항상 같은 SHA-256 해시를 만든다.
- 중간 저장 버튼을 누르기 전에는 Supabase 요청이 발생하지 않는다.
- 중간 저장 성공 시 마지막 저장 시각이 갱신된다.
- 저장 실패 시 로컬 상태가 변경되지 않는다.
- 불러오기 확인 취소 시 상태가 변경되지 않는다.
- 정상 백업 불러오기 시 앱 상태와 로컬 저장소가 함께 갱신된다.
- 깨진 클라우드 상태는 적용되지 않는다.
- Vercel Preview에서 새로고침 후 로컬 저장 유지와 수동 백업·복구를 확인한다.

## 제외 범위

- 자동 클라우드 동기화
- 여러 저장 슬롯
- 로그인 및 계정 연동
- 다른 기기 복구
- 저장 이력과 이전 버전 복원
- PostgreSQL 연결 문자열을 프런트엔드에서 사용하는 방식
