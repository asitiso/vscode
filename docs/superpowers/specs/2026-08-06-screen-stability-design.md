# 화면 안정화 설계

## 목표

새 기능을 추가하지 않고 현재 디자인과 기능 배치를 최대한 유지하면서 앱 전체 화면을 안정화한다. 최소 320px 폭의 안드로이드 세로 화면을 완전 지원하고, 가로 전환에서도 잘림·겹침 없이 스크롤 가능하게 만든다.

완료 기준은 다음과 같다.

- 가로 스크롤이 생기지 않는다.
- 하단 내비게이션이 콘텐츠를 가리지 않는다.
- 키보드가 열린 상태에서도 현재 입력칸과 저장 버튼에 접근할 수 있다.
- 팝업·모달·바텀시트가 실제 화면 높이 밖으로 벗어나지 않는다.
- 긴 운동명·메모·큰 숫자가 다른 요소와 겹치지 않는다.
- 320×568, 360×640, 390×844, 412×915 세로 화면에서 주요 흐름을 사용할 수 있다.
- 짧은 가로 화면에서도 닫기 버튼과 핵심 동작에 접근할 수 있다.

## 범위

다음 화면과 상태를 모두 점검한다.

- 홈
- 운동 기록
- 도감과 카드 상세
- 보상
- 주간·월간 운동 리포트
- 운동 상세 분석
- 카드팩
- 일반 모달
- 바텀시트
- 키보드가 열린 입력 상태
- 빈 데이터 상태
- 기록이 많은 상태

이번 업데이트에서 제외한다.

- 색상·캐릭터·카드 스타일 전면 변경
- 신규 기능
- 태블릿·데스크톱 전용 재설계
- 애니메이션 전면 개편
- 라우터 구조 변경

## 기본 방향

공통 레이아웃 규칙을 먼저 안정화한 뒤 화면별 예외만 수정한다. 화면마다 임시 CSS를 반복해서 덧붙이는 방식은 사용하지 않는다.

현재 색상, 카드 형태, 아이콘, 주요 정보 구조와 배치는 유지한다. 변경 대상은 화면 높이 계산, 스크롤, safe-area, 여백, 줄바꿈, 터치 영역과 모달 높이처럼 안정성에 직접 관계된 부분으로 제한한다.

## 공통 화면 구조

### 실제 화면 높이

`window.visualViewport`를 우선 사용해 브라우저 주소창과 소프트 키보드를 제외한 실제 표시 높이를 계산한다. 지원하지 않는 환경에서는 `window.innerHeight`를 사용한다.

공통 CSS 변수는 다음 역할로 분리한다.

- `--app-height`: 현재 실제 표시 높이
- `--viewport-height`: visual viewport 높이
- `--keyboard-height`: 계산된 키보드 높이
- `--bottom-nav-height`: 하단 내비게이션 높이
- `--safe-top`: 상단 safe-area
- `--safe-bottom`: 하단 safe-area

앱 최상위 컨테이너는 고정된 `100vh` 대신 계산된 높이를 사용한다. 각 주요 화면은 자체적으로 중복된 전체 화면 높이를 계산하지 않고 공통 값을 사용한다.

### 키보드 상태

키보드 열림은 layout viewport와 visual viewport의 높이 차이를 기준으로 판단한다. 작은 주소창 변화가 키보드로 오인되지 않도록 최소 임계값을 적용한다.

키보드가 열리면 다음 동작을 적용한다.

- 하단 내비게이션을 임시로 숨긴다.
- 현재 포커스된 입력 요소가 보이도록 스크롤한다.
- 저장 버튼과 마지막 입력 행에 접근할 수 있도록 하단 여백을 다시 계산한다.
- 모달과 바텀시트 높이를 현재 사용 가능한 viewport에 맞춘다.

키보드가 닫히면 하단 내비게이션과 기존 스크롤 구조를 복원한다.

### 공통 스크롤

주요 화면은 하나의 명확한 세로 스크롤 컨테이너를 사용한다. 동일 화면에 body 스크롤과 내부 전체 화면 스크롤이 동시에 생기지 않게 한다.

화면 마지막 콘텐츠에는 하단 내비게이션 높이와 safe-area를 합친 여백을 확보한다. 키보드가 열려 하단 내비게이션이 숨겨지면 해당 여백도 함께 조정한다.

### 텍스트와 폭 보호

공통적으로 다음 규칙을 적용한다.

- flex·grid 자식에 `min-width: 0`
- 긴 이름과 메모에 `overflow-wrap: anywhere`
- 한 줄 유지가 필요한 배지와 단위에는 `white-space: nowrap`
- 제목은 필요에 따라 최대 2줄
- 큰 숫자는 `clamp()` 기반 글자 크기 또는 줄바꿈 없는 축소 처리
- 이미지와 카드 미디어 영역은 고정 비율을 사용해 로딩 전후 높이 변화 방지

### 터치 영역

주요 버튼, 닫기 버튼, 탭, 이전·다음 버튼의 터치 영역은 최소 44×44px로 한다. 시각적 아이콘 크기는 유지하되 투명한 패딩으로 터치 영역을 확보할 수 있다.

비활성 버튼은 공간을 유지해 주변 레이아웃이 흔들리지 않게 한다. 연속 탭으로 같은 화면이나 팝업이 중복으로 열리지 않도록 기존 상태 전환도 점검한다.

## 모달과 바텀시트

모달과 바텀시트는 실제 viewport 안에 고정한다.

구조는 다음처럼 통일한다.

1. 고정 헤더: 제목과 닫기 버튼
2. 내부 스크롤 본문
3. 필요 시 고정 또는 흐름형 하단 동작 영역

최대 높이는 `--viewport-height`에서 safe-area와 외부 여백을 뺀 값으로 계산한다. 내용이 길어져도 닫기 버튼은 화면에 남는다.

모달이 열릴 때 배경 스크롤을 잠그고 현재 스크롤 위치를 저장한다. 닫힐 때 잠금을 해제하고 원래 위치를 복원한다. 중첩 오버레이가 생기는 경우 마지막 오버레이가 닫히기 전까지 배경 잠금을 유지한다.

가로 화면에서는 모달 상·하단 여백을 줄이고 내부 스크롤 영역을 확보한다. 바텀시트가 지나치게 낮아지는 경우에도 헤더와 닫기 버튼, 최소 한 개의 주요 동작은 접근 가능해야 한다.

## 화면별 기준

### 홈

- 캐릭터, 오늘의 카드, 오늘의 도전과 핵심 행동 버튼이 320px에서 겹치지 않는다.
- 긴 제목은 최대 2줄로 제한한다.
- 숫자와 배지는 한 줄을 유지한다.
- 높이가 짧은 화면에서는 장식 여백을 줄이고 핵심 행동 버튼을 우선 보이게 한다.
- 마지막 카드가 하단 내비게이션에 가려지지 않는다.

### 운동 기록

- 키보드가 열리면 포커스된 입력칸과 저장 버튼이 보인다.
- 중량·반복·세트 입력 행은 320px에서 가로로 넘치지 않는다.
- 긴 운동명은 입력칸을 밀어내지 않고 이름 영역에서 줄바꿈된다.
- 저장 버튼은 키보드와 하단 내비게이션 사이에 고정되어 겹치지 않는다. 현재 구조에 따라 흐름형으로 유지할 경우에도 자동 스크롤로 접근 가능해야 한다.
- 키보드가 열린 동안 하단 내비게이션을 숨긴다.

### 도감과 카드

- 카드 그리드는 화면 폭에 따라 열 수와 간격이 자동 조정된다.
- 카드 이름과 희귀도 배지가 이미지 영역을 침범하지 않는다.
- 이미지 영역은 비율을 유지해 로딩 전후 레이아웃이 흔들리지 않는다.
- 카드 상세 팝업은 화면 안에 고정하고 설명 영역만 스크롤한다.

### 보상과 운동 리포트

- 세 개 탭은 320px에서 줄바꿈되지 않는다.
- 기간 이동 버튼과 기간 제목이 서로 겹치지 않는다.
- 통계 카드 숫자가 커져도 카드 밖으로 넘치지 않는다.
- 주간 목록과 월간 달력이 화면 폭을 넘지 않는다.
- 긴 운동명은 분석 진입 버튼 안에서 안전하게 줄바꿈된다.

### 운동 상세 분석

- 최고 기록 카드와 누적 통계가 320px에서 적절한 열 수로 재배치된다.
- SVG 그래프는 부모 폭을 기준으로 렌더링된다.
- 모든 그래프 값이 같거나 지점이 하나뿐이어도 선과 점이 화면 밖으로 벗어나지 않는다.
- 최근 기록과 전체 기록에서 긴 운동명·메모가 줄바꿈된다.
- 상세 화면에서 뒤로가면 기존 리포트 탭, 주간·월간 모드, 기간과 스크롤 위치를 유지한다.

### 카드팩과 기타 오버레이

- 카드팩 연출이 작은 화면에서 화면 밖으로 잘리지 않는다.
- 닫기 또는 계속 버튼은 항상 접근 가능하다.
- 이미지 로딩 실패 시에도 대체 영역 크기를 유지한다.
- 연속 탭으로 카드팩 결과 화면이 중복 진행되지 않는다.

## 세로와 가로 지원

세로 화면을 완전 지원한다. 검증 기준 폭은 320, 360, 390, 412px이다.

가로 화면은 동일한 디자인 완성도를 목표로 재설계하지 않는다. 대신 다음 조건을 충족한다.

- 가로 잘림이 없다.
- 필요한 경우 세로 스크롤이 가능하다.
- 닫기 버튼과 핵심 행동에 접근할 수 있다.
- 하단 내비게이션이나 고정 버튼이 콘텐츠를 덮지 않는다.

## 오류 방지

- `visualViewport`가 없으면 `window.innerHeight`를 사용한다.
- 키보드 계산값이 음수이거나 임계값보다 작으면 키보드가 닫힌 것으로 처리한다.
- `resize`, `scroll`, `orientationchange` 리스너는 컴포넌트 해제 시 제거한다.
- 연속 viewport 이벤트는 `requestAnimationFrame` 또는 동등한 방식으로 한 프레임에 한 번 반영한다.
- 스크롤 잠금은 참조 카운트 또는 오버레이 스택으로 관리해 중첩 상태에서도 정상 복원한다.
- 잘못된 크기 계산이 발생해도 최소 높이와 최대 높이 범위를 적용한다.
- 이미지 오류 대체 UI는 원래 미디어 비율을 유지한다.

## 테스트 전략

### 자동 테스트

다음을 검증한다.

- `visualViewport`가 있을 때와 없을 때의 높이 계산
- viewport 높이 변화에 따른 CSS 변수 갱신
- 키보드 임계값 판정
- 키보드 열림·닫힘에 따른 하단 내비게이션 표시 상태
- 이벤트 리스너 정리
- 포커스 입력 요소 자동 스크롤 호출
- 모달 배경 스크롤 잠금과 복원
- 중첩 오버레이 잠금 유지
- 모달 헤더와 내부 스크롤 구조
- 리포트에서 상세 분석을 열고 돌아왔을 때 탭·기간 상태 유지
- 빈 데이터와 대량 기록 상태 렌더링
- SVG 그래프의 단일 지점과 동일값 처리

CSS만으로 보장하기 어려운 320px 오버플로 검증은 브라우저 기반 테스트 또는 수동 검증 체크리스트를 병행한다.

### 수동 검증

다음 화면 크기와 상태를 확인한다.

- 320×568 세로
- 360×640 세로
- 390×844 세로
- 412×915 세로
- 짧은 가로 화면
- 주소창이 펼쳐진 상태와 접힌 상태
- 키보드가 열린 운동 기록 화면
- 긴 운동명과 긴 메모
- 큰 통계 숫자
- 빈 기록
- 기록이 많은 전체 목록
- 카드 상세, 카드팩, 날짜 상세 바텀시트, 운동 분석 화면

## 구현 원칙

- 신규 외부 레이아웃 라이브러리를 추가하지 않는다.
- 공통 유틸과 훅은 한 가지 책임만 가진다.
- 기존 화면의 기능과 상태 구조를 불필요하게 변경하지 않는다.
- 공통 규칙으로 해결 가능한 문제를 화면별 CSS로 중복 처리하지 않는다.
- 화면별 조정은 공통 규칙 적용 후 남는 예외에만 사용한다.
- 테스트와 빌드 결과를 확인하기 전에는 안정화 완료로 표시하지 않는다.
