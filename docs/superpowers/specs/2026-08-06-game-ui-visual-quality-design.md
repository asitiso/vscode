# 게임형 UI 화질 개선 프로젝트 설계

## 목표

기존 기능, 데이터 구조, 이미지 파일, 화면 흐름을 유지하면서 앱 전체의 시각 품질을 일본 캐주얼 수집형 게임 수준으로 끌어올린다.

이번 프로젝트에서 말하는 화질 개선은 이미지 해상도 교체가 아니라 다음을 포함한다.

- 화면별 정보 계층 개선
- 게임형 패널, 버튼, 게이지, 프레임 적용
- 그림자, 외곽선, 광택, 하이라이트를 통한 깊이감 강화
- 캐릭터, 카드, 보상 요소의 시각적 집중도 향상
- 모바일 환경에서 선명하고 안정적인 레이아웃 유지

## 확정 방향

- 전체 스타일: 밝고 부드러운 일본 캐주얼 수집형 게임
- 이미지 범위: 기존 캐릭터, 카드, 카드팩 이미지를 유지
- 구조 범위: 주요 기능 순서와 정보 위치를 최대한 유지
- 변경 중심: CSS, 레이아웃 간격, 프레임, 버튼, 배경, 강조 효과
- 제외: 기능 추가, 데이터 모델 변경, 전면적인 이미지 재제작

## 핵심 원칙

### 기능 보존

- 홈, 운동 기록, 카드팩 개봉, 도감, 보상, 리포트, 분석, 설정 기능은 그대로 유지한다.
- 화면 이동과 저장 데이터 구조를 변경하지 않는다.
- 기존 게임 보상량, 카드 확률, 업적 조건을 변경하지 않는다.

### 익숙한 흐름 유지

- 사용자가 이미 익힌 정보 순서와 주요 버튼 위치를 유지한다.
- 시각적인 강조 순서는 개선하되 기능의 의미와 위치를 불필요하게 바꾸지 않는다.
- 기존 컴포넌트 구조를 최대한 활용한다.

### 절제된 게임 연출

- 모든 요소를 빛나게 하지 않는다.
- 메인 CTA, 신규 보상, 희귀 카드, 완료 임박 상태처럼 중요한 요소만 강조한다.
- 장식보다 정보 가독성과 터치 편의성을 우선한다.

## 공통 게임 UI 시스템

### 배경

- 단색 배경을 옅은 그라데이션, 빛 번짐, 미세 패턴이 있는 배경으로 개선한다.
- 본문 정보와 배경의 대비가 충분하도록 장식 투명도를 낮게 유지한다.
- 화면마다 색상을 완전히 바꾸지 않고 같은 색상 계열 안에서 변주한다.

### 패널

공통 패널은 다음 계층으로 구성한다.

1. 바깥쪽 그림자
2. 비교적 선명한 외곽선
3. 패널 본체 배경
4. 위쪽 안쪽 하이라이트
5. 필요한 경우 하단 음영

패널 종류는 다음 수준으로 제한한다.

- 일반 정보 패널
- 강조 패널
- 보상 또는 희귀도 패널
- 모달과 바텀시트 패널

### 버튼

- 위쪽이 밝고 아래쪽이 진한 수직 그라데이션을 사용한다.
- 외곽선과 아래쪽 그림자로 입체감을 준다.
- 눌렀을 때 1~2px 내려가며 그림자가 줄어드는 반응을 적용한다.
- 비활성 버튼은 단순 투명도 저하가 아니라 명도와 그림자를 함께 낮춘다.
- 모든 주요 버튼은 최소 44px 터치 영역을 유지한다.

### 게이지

- 진행률 바를 경험치 게이지 형태로 통일한다.
- 바탕, 채움, 상단 광택의 세 단계로 구성한다.
- 완료 상태는 색상과 작은 완료 배지로 표현한다.
- 퍼센트와 현재 수치를 함께 보여줄 때 텍스트가 게이지에 묻히지 않도록 분리한다.

### 배지와 상태 표시

- 레벨, NEW, 완료, 잠금, 중복 수량, 연속 기록에 공통 배지 규칙을 사용한다.
- 배지는 화면당 과도하게 사용하지 않는다.
- 아이콘과 텍스트가 함께 있을 때 텍스트 가독성을 우선한다.

### 타이포그래피

- 기존 글꼴을 유지한다.
- 제목, 핵심 수치, 설명, 보조 정보의 크기와 굵기를 명확히 나눈다.
- 숫자와 단위는 줄바꿈되지 않도록 처리한다.
- 긴 한글 이름은 말줄임 또는 고정 높이 영역으로 안정화한다.

### 디자인 토큰

공통 CSS 변수로 다음 항목을 관리한다.

- 화면 배경색과 그라데이션
- 패널 배경과 외곽선
- 강조색
- 그림자 3단계
- 패널 모서리 반경
- 버튼 모서리 반경과 높이
- 내측 하이라이트
- 희귀도별 프레임 색상
- 제목, 본문, 보조 텍스트 색상
- 화면 좌우 여백
- 하단 내비게이션 높이

## 홈 화면

홈 화면은 게임 로비처럼 보이도록 개선한다.

### 상단 HUD

- 레벨과 연속 운동 정보를 독립된 HUD 배지로 유지한다.
- 레벨 배지는 별 또는 메달 느낌의 프레임을 적용한다.
- 경험치 팝오버는 작은 게임 상태창처럼 표현한다.
- 주간 목표 숫자와 진행률이 먼저 보이도록 정보 우선순위를 조정한다.

### 주간 목표 패널

- 현재 구조를 유지하면서 경험치 게이지 형태를 적용한다.
- 목표 달성 전에는 남은 횟수를 강조한다.
- 목표 달성 후에는 완료 배지와 색상 변화로 상태를 구분한다.

### 카드 세트 진행 패널

- 현재 정보 순서를 유지한다.
- 이벤트 배너에 가까운 프레임과 배경을 적용한다.
- 세트 이름, 보유 수량, 남은 카드 정보를 명확히 분리한다.
- 완성 임박과 완료 상태의 프레임을 다르게 표현한다.

### 캐릭터 영역

- 캐릭터 이미지는 변경하지 않는다.
- 받침대, 타원형 그림자, 은은한 후광으로 캐릭터가 배경과 분리돼 보이게 한다.
- 말풍선은 NPC 대화창처럼 정리한다.
- 장식이 캐릭터 이미지를 가리지 않도록 한다.

### 운동 기록 CTA

- 홈에서 가장 강한 액션으로 유지한다.
- 입체적인 대형 버튼과 운동 아이콘을 적용한다.
- 현재 버튼 문구를 유지하고 보조 문구가 필요할 경우 짧게 제한한다.
- 터치 시 눌림 반응과 짧은 하이라이트 효과를 적용한다.

### 카드팩

- 미개봉 카드팩 위치와 동작을 유지한다.
- 약한 후광, NEW 배지, 떠 있는 느낌을 추가한다.
- 지나친 반복 애니메이션은 사용하지 않는다.

## 운동 기록 화면

기존 입력 흐름을 유지하면서 훈련 준비 화면처럼 개선한다.

### 화면 헤더

- 오늘의 운동 기록 제목을 게임형 헤더 패널로 구성한다.
- 선택된 운동 수나 현재 단계를 작은 상태 배지로 표시할 수 있다.

### 카테고리 선택

- 기존 탭 순서를 유지한다.
- 선택 탭은 프레임, 배경, 아이콘 위치로 확실하게 구분한다.
- 가로 스크롤과 작은 화면 동작은 유지한다.

### 운동 선택 카드

- 운동기구 캐릭터와 운동명을 하나의 수집형 카드로 묶는다.
- 선택 상태는 체크 배지, 강조 외곽선, 약한 후광으로 표현한다.
- 선택되지 않은 카드는 대비를 지나치게 낮추지 않는다.

### 기록 입력 카드

- 운동 이름, 캐릭터, 수치 입력을 하나의 훈련 패널 안에 정리한다.
- 중량, 횟수, 세트, 시간 입력값을 능력치 입력처럼 보이게 한다.
- 증가와 감소 버튼은 큰 터치 영역과 입체감을 적용한다.
- 긴 운동명에도 입력칸 정렬이 흔들리지 않도록 한다.

### 저장 버튼과 오류 상태

- 하단 저장 버튼은 기존 고정 흐름을 유지한다.
- 오류는 게임형 안내 배너로 표시하되 의미는 명확하게 전달한다.
- 키보드가 열린 상태에서 입력 필드와 저장 버튼이 겹치지 않도록 기존 viewport 처리를 유지한다.

## 도감 화면

현재 카드 그리드와 필터 흐름을 유지하면서 수집 앨범 느낌을 강화한다.

### 상단 정보

- 전체 수집률을 큰 게이지 또는 요약 패널로 표현한다.
- 세트 필터는 게임 도감 탭처럼 표현한다.

### 카드 프레임

- 희귀도별로 테두리와 내부 광택을 차등 적용한다.
- 카드 이미지 자체는 변경하지 않는다.
- 중복 수량은 원형 배지로 표시한다.
- 4성 또는 진화 상태에는 별 또는 프레임 광택을 추가한다.

### 미획득 카드

- 단순 회색 박스 대신 실루엣, 잠금, 획득 힌트 구조를 사용한다.
- 실제 카드 정체가 지나치게 드러나지 않게 한다.

### 세트 완성

- 완료된 세트에는 리본, 도장 또는 완료 배지를 적용한다.
- 세트 진행률과 남은 카드 수를 빠르게 파악할 수 있게 한다.

## 카드팩 개봉 화면

앱에서 가장 강한 게임 연출을 제공하되 모바일 성능을 우선한다.

- 개봉 전, 개봉 중, 결과 확인 단계를 시각적으로 분리한다.
- 카드팩 주변에 중심 광원과 가벼운 입자 효과를 적용한다.
- 희귀도별 결과 프레임과 배경을 구분한다.
- 신규 카드는 NEW 배지로 강조한다.
- 중복 카드는 강화 진행 정보를 자연스럽게 보여준다.
- `prefers-reduced-motion`에서는 단순 페이드와 확대 효과로 대체한다.

## 보상과 업적 화면

- 기존 목록과 조건을 유지한다.
- 진행 중, 완료, 잠김 상태를 프레임과 배지로 구분한다.
- 진행률은 공통 게임 게이지를 사용한다.
- 완료 업적에는 메달 또는 리본 느낌을 적용한다.
- 획득 가능한 상태는 은은한 강조만 사용한다.

## 리포트와 운동 분석 화면

분석 정보의 신뢰감은 유지하면서 플레이 기록 화면처럼 개선한다.

### 핵심 통계

- 운동 횟수, 세트 수, 시간, 연속 기록을 큰 숫자 카드로 표현한다.
- 각 통계에 작은 아이콘 프레임을 적용한다.

### 달력

- 기존 날짜 선택 동작을 유지한다.
- 운동한 날짜는 출석 스탬프 또는 체크 표시로 표현한다.
- 선택된 날짜와 오늘 날짜를 구분한다.

### 차트

- 선과 포인트를 조금 더 두껍게 표현한다.
- 최고 기록 지점은 트로피 또는 개인 기록 배지로 강조한다.
- 데이터가 없는 상태는 게임형 빈 상태 패널로 처리한다.

### 상세 기록

- 운동 상세 바텀시트는 게임 기록창처럼 프레임을 적용한다.
- 고정 헤더와 내부 스크롤 구조를 유지한다.

## 설정 화면

- 사용자 이름, 캐릭터, 주간 목표를 섹션 패널로 분리한다.
- 선택된 캐릭터는 체크 프레임과 활성 테두리로 표현한다.
- 입력창과 선택 버튼도 공통 게임 UI 규칙을 적용한다.
- 위험 동작은 일반 액션과 명확하게 구분한다.

## 하단 내비게이션

- 탭 순서와 동작을 유지한다.
- 활성 탭은 아이콘이 조금 위로 올라오고 배경 플레이트가 나타난다.
- 비활성 탭은 대비를 낮춘다.
- 탭 전환 시 짧은 확대 또는 눌림 효과를 적용한다.
- safe-area, 44px 터치 영역, 키보드 오픈 시 숨김 동작을 유지한다.

## 모달과 바텀시트

- 카드 세트 완료 모달, 운동 상세 시트, 카드 상세 등 오버레이 UI에 공통 프레임을 적용한다.
- 화면 높이를 넘지 않도록 내부 스크롤을 유지한다.
- 헤더와 주요 액션은 스크롤에 묻히지 않게 한다.
- 배경 딤과 패널 그림자 강도를 통일한다.

## 애니메이션 원칙

- 애니메이션은 상태 이해를 돕는 용도로만 사용한다.
- 버튼 눌림, 탭 활성화, 보상 등장, 카드팩 개봉에 집중한다.
- 무한 반복 효과는 최소화한다.
- transform과 opacity 중심으로 구현한다.
- `prefers-reduced-motion`을 지원한다.

## 반응형과 안정성

- 320px 너비부터 레이아웃이 깨지지 않아야 한다.
- 긴 한글 이름과 큰 숫자에도 패널 높이가 안정적이어야 한다.
- 가로 화면과 짧은 세로 화면에서 스크롤 접근이 가능해야 한다.
- 키보드, 모달, 바텀시트, 하단 내비게이션이 겹치지 않아야 한다.
- 기존 visualViewport 및 safe-area 대응을 유지한다.

## 구현 구조

### 공통 레이어

- 공통 게임 UI 토큰 파일을 추가하거나 기존 전역 스타일에 분리한다.
- 패널, 버튼, 배지, 게이지, 헤더 등 반복 패턴을 공통 클래스로 구성한다.
- 화면별 CSS는 공통 토큰을 사용해 변형만 담당한다.

### 화면별 변경

1. 공통 토큰과 기본 컴포넌트 스타일
2. 홈 화면
3. 운동 기록 화면
4. 도감과 카드 상세
5. 카드팩 개봉과 보상
6. 리포트와 운동 분석
7. 설정, 하단 내비게이션, 모달 통합

## 테스트와 검증

### 자동 검증

- 기존 기능 테스트가 유지돼야 한다.
- 변경된 상태 클래스나 접근성 속성이 있다면 관련 렌더링 테스트를 수정한다.
- `npm test` 통과
- `npm run build` 통과

### 수동 검증

Vercel Preview에서 다음 항목을 확인한다.

- 320px, 360px, 390px, 430px 너비
- 짧은 세로 화면과 가로 화면
- 홈 주요 정보 겹침 여부
- 기록 화면 키보드 입력
- 도감 긴 카드명과 미획득 카드
- 카드팩 개봉 애니메이션
- 보상과 업적 상태 구분
- 달력과 차트 가독성
- 모달과 바텀시트 내부 스크롤
- 하단 내비게이션 safe-area

## 완료 조건

- 모든 주요 화면이 같은 일본 캐주얼 수집형 게임 UI 언어를 사용한다.
- 기존 이미지와 기능이 그대로 유지된다.
- 홈, 기록, 도감, 보상, 리포트 화면의 정보 우선순위가 더 명확해진다.
- 패널, 버튼, 게이지, 배지의 시각 품질과 깊이감이 개선된다.
- 모바일 화면에서 깨짐, 겹침, 잘림이 발생하지 않는다.
- 애니메이션이 성능 저하를 일으키지 않는다.
- 자동 빌드와 Vercel Preview 검증을 완료한다.
